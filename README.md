# Модуль Redis cache для OkayCMS

Модуль додає Redis-кеш для частини запитів у магазині, щоб сторінки і блоки відкривалися швидше та створювали менше навантаження на сервер.

## Можливості

### Кешування даних магазину

Модуль кешує популярні дані, які часто запитуються на фронтенді, зокрема:

- списки товарів;
- частини даних товару (варіанти, зображення, характеристики);
- фільтри каталогу;
- бренди, автори, блог;
- валюти.

### Гнучкі TTL (час життя кешу)

- Можна окремо налаштувати TTL для кожного блоку в адмінці.
- Якщо не вказувати окреме значення, використовується TTL за замовчуванням.

### Керування кешем в адмінці

- Увімкнення/вимкнення Redis-кешу.
- Перевірка підключення до Redis кнопкою «Протестувати підключення».
- Перегляд базової статистики (кількість ключів, використана пам’ять).
- Очищення кешу модуля кнопкою «Очистити кеш цього модуля»: чужі ключі в тій самій Redis DB (сесії, черги) лишаються.

## Вимоги

- Перевірено на PHP 8.5

- Запущений Redis сервер (локально або на окремому сервері)

## Встановлення

### Варіант 1: Скачування з GitHub

1. Скачайте останню версію модуля з [останнього релізу на GitHub](https://github.com/devSviat/Redis-OkayCMS/releases/latest).
2. Розпакуйте архів на сервері в каталог: `{OkayCMS_root}/Okay/Modules/`

### Варіант 2: Встановлення через Git

1. Виконайте команду в директорії `{OkayCMS_root}/Okay/Modules/Sviat`:
   ```bash
   git clone https://github.com/devSviat/Redis-OkayCMS.git Redis
   ```

### Результат встановлення

Шлях до модуля має бути таким:
```bash
{OkayCMS_root}/Okay/Modules/Sviat/Redis/
```

Після встановлення перейдіть в адмін-панель → Модулі → Знайдіть «Redis cache» → Натисніть «Встановити».

## Де зберігати підключення

Модуль шукає параметри в такому порядку, перше знайдене значення перемагає:

1. Змінні оточення `REDIS_HOST`, `REDIS_PORT`, `REDIS_DB`, `REDIS_USERNAME`, `REDIS_PASSWORD`, `REDIS_PREFIX`, `REDIS_ENABLED`. Зручно для Docker.
2. Файл `config/config.local.php`. Рекомендовано для звичайного хостингу.
3. Форма в адмін-панелі. Найпростіший варіант, але пароль лежить у таблиці налаштувань.

Для `config/config.local.php` додайте в кінець файлу:

```ini
[redis]
redis_enabled = 1
redis_host = 127.0.0.1
redis_port = 6379
redis_db = 0
redis_password = 'ваш-пароль'
redis_prefix = shop1:
```

Потрібні лише ті рядки, які ви хочете закріпити. Пароль беріть в одинарні лапки, щоб спецсимволи читались буквально. Для `redis_enabled` використовуйте `1` або `0`. Файла може не бути: тоді скопіюйте `config/config.local-example.php`, якщо він є, або створіть файл із першим рядком `;<? exit(); ?>`. Цей файл не потрапляє в оновлення магазину.

**Що це дає:**

- Пароль не потрапляє в базу, а отже, і в її дампи та резервні копії.
- Менеджер із правом `settings` не може змінити хост і забрати пароль: поля, задані поза адмінкою, у формі лише для читання. Якщо пароль заданий поза адмінкою, хост, порт і користувач теж блокуються.
- Налаштування бази й Redis лежать в одному місці, і перенесення сайту не вимагає правок в адмінці.

**Швидкість від цього не зміниться.** Магазин і так читає налаштування на кожному запиті, тож різниця між джерелами менша за мікросекунду. Прискорення дає сам Redis. Вибір джерела стосується безпеки й зручності.

## Налаштування

1. Перейдіть в адмін-панель → Модулі → Redis cache.
2. Увімкніть перемикач «Увімкнути Redis кеш».
3. Заповніть підключення, якщо воно не задане в `config.local.php` чи env:
   - Host
   - Port
   - DB
   - Username (якщо використовуєте ACL)
   - Password (якщо потрібна авторизація)
4. За потреби вкажіть:
   - префікс ключів;
   - TTL за замовчуванням.
5. Натисніть «Протестувати підключення».
6. Якщо все добре — натисніть «Зберегти».
7. За потреби задайте час зберігання на вкладці «Час зберігання»: загальний або окремий для кожного типу даних.

## Важливо

- Кеш працює тільки на фронтенді; адмін-запити не кешуються.
- Очищення кешу видаляє лише ключі цього модуля (`<префікс>helpers:*`). Магазини зі спільним Redis мають використовувати різні префікси.
- Очищення йде проходами `SCAN`, тож на дуже великій базі воно не миттєве.
- Redis має дозволяти `EVAL`. Якщо його заборонено, кеш працює, але замок перерахунку знімається лише через 60 с.
- Порожнє поле пароля зберігає поточний пароль, а галочка «Видалити збережений пароль» його видаляє. Введений новий пароль має пріоритет над галочкою.
- Якщо Redis недоступний, сайт продовжить працювати без кешу.
- На сторінці товару модуль заздалегідь бере маршрут цього товару одним запитом. Без цього ядро читає всю таблицю маршрутів заради мовного перемикача.
- Якщо змінити хост, порт або користувача й лишити поле пароля порожнім, збережений пароль видаляється: він не піде на новий сервер.
- Курси валют модуль не кешує: вони впливають на ціну в кошику, а ядро й так читає їх один раз за запит.
- Значення в кеші підписані HMAC. Ключа в Redis немає: він виводиться з доступу до БД або задається як `REDIS_SIGNING_KEY` чи `redis_signing_key`. Підпис охоплює і ключ кешу, тому значення не можна перенести під інший ключ. Запис у Redis без ключа сприймається як промах. Після оновлення модуля старі записи просто перераховуються.
- Задайте Redis пароль і `maxmemory`: підпис не захищає від читання кешу й від переповнення пам'яті.
